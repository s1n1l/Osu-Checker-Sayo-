# osu-checker

<img src="assets/logo.png" width="96" align="right">

Аналізатор гри в osu! для **SayoDevice O3C** з магнітними свічами Gateron
KS-20. Порівнює те, що реально зробили пальці й рука, з тим, що зарахувала
гра, і розділяє помилки на техніку, налаштування девайса та налаштування гри.

Мови: **[English](README.md) · Українська · [中文](README.zh.md)**

---

## Завантаження

Візьми `osu-checker-windows.zip` з [Releases](../../releases), розпакуй
куди завгодно і запусти `osu-checker.exe`. Тільки Windows, Python не
потрібен.

## Вкладки

### Аналіз

Перетягни `.osr` у вікно або натисни *Останній реплей osu!*. Працюють і
osu!stable, і експортовані реплеї osu!lazer.

**Огляд** — похибка та UR окремо по кожній руці, гістограма з межами вікон
300/100, похибка протягом карти і таблиця по BPM. Ключова колонка —
**дрейф**: наскільки похибка виросла від початку до кінця стріму.

**Аім** — куди лягав курсор відносно центра ноти. Три різні речі, які часто
плутають:

| Показник | Що означає |
|---|---|
| зміщення | курсор стабільно лягає збоку |
| розкид | лягає навколо центра, але далеко від нього |
| переїзд | проскакує ціль і повертається |

Плюс розбивка за довжиною стрибка і за напрямком на вісім секторів.

**Проблемні моменти** — найдорожчі відрізки карти з часом, втратами і
причиною: *не встиг*, *поспішив*, *розкид*, *аім*.

### Запис сесії

Три джерела одночасно:

| Джерело | Що дає | Частота |
|---|---|---|
| Raw Input | натискання тільки з O3C | подієво, ~1 мс |
| HID-опитування | хід усіх трьох клавіш у мкм | ~2660 Гц (0.37 мс) |
| GetCursorPos | положення курсора | опитування 500 Гц |

Це потрібно тому, що реплей osu! пише лише ~62 кадри на секунду, тобто
округлює будь-який таймінг до ~16 мс. Після зупинки вкладка показує реальну
глибину натиску по кожній клавіші й запас до точки спрацювання.

Збережений запис можна прикріпити на вкладці «Аналіз» — тоді до висновків
додається глибина натиску, якої в реплеї немає в принципі.

### Тренування

План будується з цифр останнього аналізу. У кожної вправи є **вимірюваний
критерій**, який цей же застосунок перевіряє на наступному реплеї. Кнопка
*Підібрати мапи* шукає у твоїй колекції карти зі стрімами потрібного BPM.

### Налаштування

Мова, шляхи до osu! та індекс мап (MD5 → `.osu`).

## Як розрізняються причини

| Що видно в даних | Висновок |
|---|---|
| Похибка росте від початку до кінця стріму | Бракує швидкості, рука не тримає темп |
| Натисків більше, ніж нот, при рівній похибці | Оверстрім |
| Ліва і права рука мають різну середню похибку | Розсинхрон рук, техніка |
| Рівний зсув на багатьох реплеях | Офсет або затримка звуку |
| Повторний натиск швидше 45 мс | Подвійне спрацювання, Rapid Trigger |
| Курсор далеко від центрів на цій ділянці | Сипався аім, а не стук |
| Глибина натиску ледве перевищує поріг | Недотиск, знизити точку спрацювання |

## Пристрій

SayoDevice O3C, `VID 0x8089 / PID 0x0009`. Застосунок **тільки читає**: шле
запити на читання стану, конфігурацію не чіпає.

Протокол — **запит/відповідь**, не потік. Девайс мовчить, поки його не
спитають; веб-конфігуратор опитує його ~20 разів на секунду, через що збоку
це виглядає як потік.

Стеля залежить від частоти опитування USB, виставленої в самому девайсі. При
**8000 Гц** один оборот займає **0.37 мс** — приблизно три USB-кадри, тобто
всі три клавіші можна знімати близько 2660 разів на секунду. При 1000 Гц
оборот був би ~2 мс.

Запит, usage page `0xFF12`, пакет 1024 Б:

```
0x00  report_id 0x22
0x01  echo 0x03
0x02  checksum u16 LE   (сума пакета як u16 із занудьованим слотом)
0x04  len u16 LE = 0x0004
0x06  id 0x15
0x07  index 0x01        <- саме index=1 дає міліметри
```

Відповідь: `len=0x000a`, далі три `u16` — хід клавіш у мікрометрах, `0` у
спокої і `4000` при повному ході 4 мм. `index=0` віддає сирий ADC однієї
клавіші, `index=2` — сирий ADC усіх трьох. Індекси клавіш: `P = 0, V = 1,
B = 2`.

Інтерфейс `0xFF11` говорить тим самим протоколом у 64-байтних пакетах; запит
`0x1F` віддає 16 послідовних семплів однієї клавіші, але клавіша там не
перемикається, тому використовується `0xFF12`.

Частоту опитування можна обмежити у вкладці «Запис сесії», але сенсу в цьому
мало: вільний хід коштує ~9% одного ядра, і це дешевше за будь-яке точне
обмеження — дочікування кванта на Windows з'їдає більше, ніж економить.

### Обмеження

- Кількість 50 і miss трохи розходиться з osu!, бо гра окремо судить голови
  слайдерів. Кількість 300 збігається з точністю ~0.1%, і саме на ній
  будується аналіз стуку.
- Прив'язка запису сесії до реплею ручна: глибина натиску береться агрегатом
  по всій сесії, без суміщення з окремими нотами.
- Геометрія ігрового поля для курсора рахується за формулою osu!stable
  (512×384 у віртуальному екрані 640×480 зі зсувом на 8 віртуальних пікселів
  вниз) і знімається з вікна osu!, поки воно активне.

## Про автоповтор клавіш

Утримана клавіша змушує Windows слати `WM_KEYDOWN` кожні ~30 мс після паузи
~500 мс, і Raw Input їх теж віддає. Рекордер відкидає їх за станом клавіші —
інакше двосекундне утримання виглядало б як 50 натискань.

## Приватність

Рекордер працює через Raw Input, який повідомляє HID-хендл пристрою.
Пишуться лише події з `VID_8089&PID_0009`, і за замовчуванням лише поки
активне вікно osu!. Те, що набирається на звичайній клавіатурі, застосунок
не бачить.

## Збірка з вихідників

Windows, Python 3.12+.

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Зібрати папку для розповсюдження:

```
.venv\Scripts\python.exe -m pip install pyinstaller pillow
.venv\Scripts\python.exe tools\make_icon.py
.venv\Scripts\python.exe tools\build.py
```

Результат — `dist\osu-checker\`; заархівуй цю папку, і вона запуститься на
будь-якій машині з Windows без Python. Збірка свідомо `onedir`: `onefile`
щоразу розпаковує ~160 МБ у тимчасову теку.

## Діагностика

У зібраного застосунку є самоперевірка, яка працює без вікна і пише звіт у
`%APPDATA%\osu-checker\selftest.txt`:

```
osu-checker.exe --selftest
osu-checker.exe --selftest "шлях\до\реплею.osr"
```

Перевіряє імпорт `osrparse`, іконку, видимість девайса по HID, розмір індексу
мап і, якщо дано шлях, повний розбір реплею. Це потрібно саме для збірки:
частина проблем виникає лише після PyInstaller, а вікно без консолі їх не
показує.

## Дані застосунку

У режимі розробки — папка `data/`. У зібраному застосунку —
`%APPDATA%\osu-checker`: `config.json`, індекс мап `beatmap_index.json` і кеш
профілів `map_profiles.json`.

## Як додати мову

Скопіюй `osuchecker/translations/en.py`, переклади значення, залиш ключі та
`{підстановки}` незмінними, і додай код мови в `LANGUAGES` у файлі
`osuchecker/i18n.py`.

## Подяки

Протокол O3C розібраний на самому девайсі; формат кадру спирається на
публічні нотатки з реверс-інжинірингу від
[khang06](https://gist.github.com/khang06/6186543b560548370ce7cc08cad7f710)
і на clean-room прошивку
[ankurCES/sayofw-o3c](https://github.com/ankurCES/sayofw-o3c).

Реплеї читаються через [osrparse](https://github.com/kszlim/osu-replay-parser).

Проєкт не пов'язаний з osu! чи SayoDevice.
